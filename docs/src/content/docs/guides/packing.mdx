In Roblox, image performance is primarily a battle against draw calls. If your UI uses 50 individual images, the engine treats them as 50 separate tasks to load and render. By consolidating these into a single spritesheet, you allow the engine to process everything in a single pass—effectively slashing 50 draw calls down to just one.

In this guide, we'll walk through how Tungsten automates the complex math of packing images and generates the code needed to use them.

## Organizing your Assets

To pack assets, Tungsten needs to know which files belong together. The cleanest way to do this is by organizing your `assets/` folder.

Let's say you have a set of UI icons. Arrange them like this:

<FileTree>

- **assets/**
  - icons/
    - home.png
    - settings.png
    - user.png
    - menu.png

</FileTree>

## Configuring the Pack

By default, Tungsten syncs files individually. To bundle them into a spritesheet, you need to define an `[inputs]` entry in your `tungsten.toml` with `packable = true`.

```toml title="tungsten.toml"
[inputs.ui_icons]
path = "assets/icons/**/*"
output_path = "src/IconSheet.luau"
type = "image"
packable = true
```

### Configuration Breakdown

- `path`: A glob pattern defining which images Tungsten should combine.
- `output_path`: The file path where Tungsten will generate the Luau module containing your asset references.
- `packable`: A boolean flag that explicitly enables the spritesheet packing logic for this group.

### Multiple Atlases

If your images put together exceed 1024×1024, Tungsten automatically creates additional sheets (`Sheet_001`, `Sheet_002`, etc.) and generates code that references the correct sheet per sprite.

## Alpha Bleeding

When sprites are packed into a sheet and scaled in Roblox, transparent edges can show dark fringes from neighboring sprites. Tungsten automatically applies **alpha bleeding** (color expansion into transparent pixels) to prevent this.

To disable for specific inputs (e.g., full-frame backgrounds):

```toml
[inputs.backgrounds]
path = "assets/backgrounds/**/*"
output_path = "src/Backgrounds.luau"
type = "decal"
bleed = false  # Disable alpha bleeding
```

Default: `true` for all packed and individual images.

## Syncing the Sheet

Run your sync command:

```bash title="Terminal"
tungsten sync cloud
```

When Tungsten runs, it performs the following:

<Steps>

1. #### Scans

   Locates all images matching your path glob pattern.

2. #### Calculates

   Computes the most efficient layout using a rect-packing algorithm (max 1024×1024 per sheet).

3. #### Generates

   Creates the optimized spritesheet image(s) and the `output_path` Luau module.

4. #### Uploads

   Pushes the spritesheet(s) to Roblox.

5. #### Updates

   Refreshes your code generation file with the correct coordinates.

</Steps>

:::tip[Why this matters]
On mobile devices and lower-end hardware, every draw call has a performance cost. Spritesheets are the single best way to ensure your UI stays responsive regardless of the device.
:::

## Using your Sprites

Tungsten generates type-safe code with `ImageRectOffset` and `ImageRectSize` pre-calculated.

```luau title="HomeIcon.luau"
local Assets = game.ReplicatedStorage.Assets

-- Require the module Tungsten generated
local Icons = require(Assets.IconSheet)

local home = script.Parent

-- Apply the sprite properties automatically
home.Image = Icons.home.Image
home.ImageRectOffset = Icons.home.ImageRectOffset
home.ImageRectSize = Icons.home.ImageRectSize
```

Tungsten handles the "boring" math of sprite coordinates, so you can simply point your `ImageLabel` to the asset reference generated by the tool.
